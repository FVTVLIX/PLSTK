# Project guidance

## Product direction

Keep everyday editing visual and approachable. Prefer icons with short labels, direct manipulation, presets, and sliders. Put exact values in contextual Fine tune controls. Preserve a clear route back to the Library.

## Verification

Use focused checks appropriate to the change. Media behavior needs preview and export verification. Native interaction changes need UI inspection. Use synthetic media and protect existing user projects.

## Commits

The owner requests a commit after each completed major update. Review the staged files, diff, and verification results first. Use a clear title and a short body covering behavior and validation. Do not create empty checkpoint commits or rewrite unrelated history.

Use the repository's GitHub noreply identity for public commits. Do not change global Git identity settings. Remote publication should remain within the user's authorized scope.

## Public writing

Use professional, human language. Avoid hyphenated prose and dash style lists. Preserve required punctuation in exact commands, paths, URLs, and license identifiers.

## Privacy and licensing

Do not commit local reference archives, extracted third party material, personal footage, credentials, signing keys, generated projects, or local machine configuration. Review new public documents and images explicitly before allowing them through `.gitignore`.

The source is licensed under GNU GPL version 3 only. Preserve LICENSE and COPYRIGHT. Record new dependency terms in THIRD_PARTY_NOTICES.md. Do not bundle media tools without reviewing their exact license and source distribution requirements.
